**서버 사이드 파라미터 오염(Server-side Parameter Pollution)** 은 웹 애플리케이션 보안 취약점 중 하나입니다.

## 기본 개념

서버 사이드 파라미터 오염은 웹사이트가 사용자 입력을 내부 API로 전송할 때 적절한 인코딩 없이 그대로 삽입함으로써 발생하는 취약점입니다. 일반적으로 인터넷에서 직접 접근할 수 없는 내부 API들이 이런 방식으로 악용될 수 있습니다.

## 발생 원리

1. **사용자 입력 수집**: 웹 애플리케이션이 사용자로부터 데이터를 받습니다
2. **내부 API 호출**: 이 데이터를 내부 API 요청에 포함시킵니다
3. **부적절한 처리**: 사용자 입력을 적절히 검증하거나 인코딩하지 않고 그대로 전달합니다
4. **파라미터 조작**: 공격자가 추가 파라미터를 주입하거나 기존 파라미터를 조작할 수 있게 됩니다

## 공격 가능한 영역

다음과 같은 모든 사용자 입력 지점에서 테스트할 수 있습니다:

- **쿼리 파라미터**: URL의 ?key=value 부분
- **폼 필드**: HTML 폼의 입력 필드들
- **HTTP 헤더**: 요청 헤더 값들
- **URL 경로 파라미터**: URL 경로의 일부분

## 공격자가 할 수 있는 것들

**기존 파라미터 덮어쓰기**: 원래 설정된 파라미터 값을 변경하여 권한을 우회하거나 다른 사용자의 데이터에 접근할 수 있습니다.

**애플리케이션 동작 수정**: 내부 API의 동작을 의도하지 않은 방향으로 변경할 수 있습니다.

**무단 데이터 접근**: 원래 접근할 수 없는 데이터나 기능에 접근할 수 있습니다.

## 실제 예시 시나리오

사용자가 프로필을 업데이트하는 기능이 있다고 가정해봅시다:

```
사용자 입력: name=John&age=25
내부 API 호출: /api/update?user_id=123&name=John&age=25
```

공격자가 다음과 같이 입력하면:

```
사용자 입력: name=John&age=25&user_id=456
최종 API 호출: /api/update?user_id=123&name=John&age=25&user_id=456
```

이 경우 내부 API가 마지막 user_id 값을 사용한다면, 공격자는 다른 사용자(456)의 정보를 수정할 수 있게 됩니다.

## 방어 방법

**입력 검증**: 모든 사용자 입력에 대해 엄격한 검증을 수행해야 합니다.

**적절한 인코딩**: 사용자 입력을 내부 API로 전달할 때 적절히 인코딩하고 이스케이프 처리해야 합니다.

**화이트리스트 방식**: 허용된 파라미터만 전달하도록 제한해야 합니다.

**파라미터 분리**: 사용자 입력과 시스템 파라미터를 명확히 분리해야 합니다.

이 취약점은 HTTP 파라미터 오염이라고도 불리지만, WAF 우회 기법과 혼동을 피하기 위해 서버 사이드 파라미터 오염이라는 용어를 사용하는 것이 좋습니다. 또한 이름이 비슷하지만 서버 사이드 프로토타입 오염과는 완전히 다른 취약점입니다.
